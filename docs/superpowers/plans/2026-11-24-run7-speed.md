# Run 7 "Speed" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Make every later run faster and cheaper (fast commit check, one shared e2e server, change-aware CI audits,
smaller docs, model routing) without lowering the quality bar.

**Architecture:** Two branches. A (`perf/fast-checks`): timings, `check:fast`, the shared e2e server, unit-test
overhead, `scripts/board-changed.mjs` for CI. B (`docs/process-diet`): PROCESS.md, `check:process`, docs diet,
CLAUDE.md/AGENTS.md merge. Owner-only files (hooks, ci.yml, agents) are `.proposed` files plus one batch script in
the scratchpad.

**Tech stack:** Node 22.19+ (`node:test`, type stripping), wrangler 4.160.1 (`unstable_startWorker`,
`getPlatformProxy`), npm 10.9.9. No new dependencies.

**Spec:** the run 7 brief in the owner's message (2026-11-24); CLAUDE.md; AGENTS.md.

## Global Constraints

- Never remove a test, weaken an assertion, lower a threshold or change which checks are required.
- `npm run check` stays the full suite (check:config, lint, typecheck, test:worker = unit + e2e, build).
- No `paths:` or job-level `if:` on `check`, `a11y`, `lighthouse`, `dependency-review`; no `[skip ci]`.
- Caps: STATUS.md max 150 lines; the newest plan max 150 lines; "For the master" max 12 lines, no PR numbers.
- One plain command per Bash call (CLAUDE.md "Command style"). Installs only via `npx --yes npm@10.9.9`.
- The current hook runs the full `npm run check` on every commit until the owner copies the new hook, so this run
  commits less often (one commit per task).

## Review Focus

1. `check:fast` picks too few tests (a changed helper, migration, seed or config file): these fall back to all unit tests.
2. A fresh e2e database per file really is fresh: a file that writes rows must not see another file's rows.
3. The e2e server exits on failure or Ctrl-C (no orphaned workerd), same as `stop()` today.
4. `board-changed.mjs` falls back to "changed" when git fails or the base is missing (never skips by mistake).
5. `check:process` reports which rule failed and how to fix it, in plain English.

### Task 2 (A): `npm run check:fast`

**Files:** Create `scripts/check-fast.mjs`, `scripts/test-select.mjs`, `scripts/test-select.test.mjs`. Modify
`package.json`, `.gitignore` (lint and tsc caches go under `node_modules/.cache/`, so nothing new to ignore).

**Interfaces:** `selectTests({ changed: string[], files: Map<string, string> }) => { mode: "all" | "some" | "none",
tests: string[], reasons: string[] }`. `files` maps every tracked or untracked `src/**`, `scripts/*`, `tests/helpers/*`
path to its source text.

- [ ] Tests first (`scripts/test-select.test.mjs`): changed `src/a.ts` selects `src/a.test.ts` and the tests of every
  file that imports `./a.ts`; a changed test selects itself; a `docs/*.md` change selects only tests whose source
  names that path; `package.json`, `package-lock.json`, `tsconfig*.json`, `eslint.config.*`, `wrangler.jsonc`,
  `migrations/**`, `seed/**`, `tests/helpers/workers-runtime.mjs` give `mode: "all"`; any other non-code path no
  test names gives `"all"`; a deleted file gives `"all"`; nothing changed gives `"none"`.
- [ ] `scripts/check-fast.mjs`: changed = `git diff --name-only <merge-base main>` + untracked
  (`git ls-files --others --exclude-standard`); git failure gives "all". Runs in order: check:config,
  `eslint --cache --cache-location node_modules/.cache/eslint/ .`, `tsc --noEmit --incremental --tsBuildInfoFile
  node_modules/.cache/tsc/worker.tsbuildinfo` and the same for `-p tests/a11y`, then `node --test` with the
  same flags as `test:unit` on the selected files. Prints each step's seconds and why tests were picked.
- [ ] `package.json`: `"check:fast": "node scripts/check-fast.mjs"`. Target under 45 s for a one-file change.
- [ ] Commit `feat: npm run check:fast`.

### Task 3 (A): Shared e2e server, unit overhead

**Files:** Create `scripts/e2e.mjs`. Modify `tests/e2e/harness.ts`, `package.json` (`test:e2e`), maybe `scripts/dev.mjs`.

**Interfaces:** `startDevServer({ extraVars })` and `prepareState(prefix)` keep their signatures and `DevServer`
shape (`url`, `stateDir`, `runCron`, `output`, `stop`), so no test file changes beyond imports.

- [ ] Template state: set up migrations, defaults and seed once per run (`scripts/e2e.mjs`), and give each file a
  copy (`cpSync`) instead of 3 wrangler spawns per file.
- [ ] One server: `scripts/e2e.mjs` builds `out/`, starts the Worker once (wrangler `unstable_startWorker`, same
  vars as `wranglerDevArgs`, cron test route), and a loopback control port (env `E2E_CONTROL_URL`). A file's
  `startDevServer()` asks it to switch to a new copy of the template with its `extraVars`, and `stop()` releases it.
  Files run one at a time, because they share the server. If the server can't switch databases reliably (cron route,
  vars, a stale row seen), fall back to per-file `wrangler dev` servers from template copies, run 3 at a time, and
  record why in decision 0052.
- [ ] Unit overhead: time `test:unit` with `--test-isolation=none` (if the Node 22.19 CI uses accepts it). Use it in
  `check:fast` only if every test passes with the same count; the full `check` keeps one process per file.
- [ ] Verify: `npm run test:e2e` passes with the same test count as before (record both), under 60 s; a run killed
  with Ctrl-C leaves no `workerd` process (`pgrep workerd` empty).
- [ ] Commit `perf: one e2e server for all files`.
