# 0002: `site.config.ts` and its generator are removed, not repurposed

## Context

The website template kept every client value (names, email, domain, provider ids) in a tracked `site.config.ts`, and
`scripts/sync-config.mjs` generated `wrangler.jsonc` and other files from it; `npm run check:config` checked they were in
sync. The spec says every copy runs identical code, nothing client-specific goes in the repo, and the repo is public.
It asked to repurpose or replace that file and record the choice.

## Decision

Remove `site.config.ts` and `scripts/sync-config.mjs`. Per-copy values live in three places only:

1. That copy's D1 `settings` row (timezone, brief hour, brief address, owner emails), changed by talking to the AI.
2. That copy's Cloudflare bindings and secrets (set by the owner with wrangler; names in `docs/SECRETS.md`).
3. A git-ignored per-copy wrangler config, `/.copies/<name>/wrangler.jsonc`, generated by the provisioning script
   (task 11). Exports go to the git-ignored `/exports/`.

The tracked `wrangler.jsonc` is a generic local-development config (`pipeline-dev`) with placeholder ids only.

`npm run check:config` keeps its name, because the required CI job `check` runs it, and becomes a guard
(`scripts/check-config.mjs`) that fails when:

- a tracked file holds an email address outside `example.com`, `example.test`, `example.org`, `example.net` (or the
  commit-trailer addresses `noreply@anthropic.com` and `*@users.noreply.github.com`); `package-lock.json` is skipped
  because npm writes it from registry metadata;
- `wrangler.jsonc` has a `database_id`, `preview_database_id` or `account_id` that is not a placeholder (`[[...]]`,
  the all-zero UUID, or `local`);
- `.gitignore` does not ignore `/.copies/` and `/exports/`, or a file under them is tracked.

## Why

- A tracked config file that holds client values contradicts "nothing client-specific in the repo". Repurposing it as
  an empty template would invite someone to fill it in and commit it.
- Settings the owner changes by talking belong in the database, where writes are audited and undoable.
- The guard turns the "no real data" rule into a failing check instead of a convention.

## Consequences

- The email check is a heuristic: it catches addresses, not names or phone numbers. Reviews still matter.
- Later tasks that add D1, KV or rate-limit bindings must use placeholder ids in `wrangler.jsonc`.
